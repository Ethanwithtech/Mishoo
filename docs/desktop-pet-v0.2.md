# Mishoo 桌面宠物 v0.2

## 产品定位

桌宠不是与现有 Mishoo 分离的新产品，而是“休息守护”的常驻入口：

1. 用户平时在桌面上看到自己的宠物，启动/暂停 25 分钟专注计时。
2. 轻提醒由桌宠气泡完成，降低普通系统通知的冷冰冰感。
3. 到达强休息节点时，继续复用现有全屏 `Pawse Mode`。
4. 官网负责获客、付费和上传宠物；Electron 桌宠与浏览器插件负责高频使用。

商业化主线不是单独售卖桌面宠物，而是让用户在现有浏览器休息守护中使用自己的宠物。桌面宠物复用同一份自动处理后的宠物资产，作为第二使用入口。

### 最小商业闭环

- 单一价值：让用户自己的宠物常驻桌面，并在该休息时主动出现。
- 自动商品：用户上传已有动作视频，系统完成诊断、抠像、转码、质检、同步和下载。
- 失败策略：自动切换参数/模型重试；仍失败则返还额度并提示重传，不进入人工队列。
- 首批目标：10 位每天使用电脑 6 小时以上的宠物主人，至少拿到 3 笔真实付款。
- 反馈方式：交付后第 3 天回访“每天看到几次、提醒是否烦、是否更愿意休息、是否愿意推荐”，用真实使用决定下一步自动化什么。

## 本轮实现

- Electron 启动时创建透明、无边框、置顶、任务栏隐藏的桌宠窗口。
- 熊猫使用从现有原视频裁切得到的透明 `idle.webm` 循环播放吃竹子动作；没有重绘、换脸或修改主体造型。
- 桌宠自动水平巡逻，碰到屏幕左右边缘掉头；连续行走 7–12 秒后随机待机 2–4 秒，再继续循环。
- 拖动、打开右键菜单或待办面板时自动暂停巡逻，避免窗口与用户操作争抢。
- 左键拖动；单击依次播放跳跃、压扁回弹、左右抖动，并启动/暂停番茄计时。
- 滚轮缩放 60%–200%。
- 右键原生菜单：开始/暂停、设置、待办、调整大小、置顶开关、退出。
- 25 分钟工作 / 5 分钟短休；每完成 4 轮进入 15 分钟长休。
- 喝水 60 分钟、久坐 45 分钟提醒；气泡、轻提示音、延后 10 分钟。
- 本地待办新增、勾选、删除，自动保存到 `localStorage`。
- 使用现有熊猫正面素材；清理脚本只保留最大连通主体，删除断开的字幕/水印碎片，不重绘角色。
- Mishoo 官网下载区已接入真实 Windows portable EXE；构建时排除该下载文件，避免 EXE 被递归打进自身。

## 八方向转头素材审计

已从 `public/videos/panda-bamboo-source.webm` 按 1 fps 抽帧生成：

`artifacts/direction-audit/panda-contact-sheet.jpg`

审计结论：这段素材是熊猫从下方出现并吃竹子的动作，包含位置与身体动作变化，但没有稳定的上、右上、右、右下、下、左下、左、左上八个头部朝向。因此它不能用于方向 sprite，也不能建立真实的 `ANGLE_KEYS` 校准表。

当前桌宠已交付经过审计的正面静态封面帧和透明待机视频：

`public/desktop-pet/framefront.webp`

`public/desktop-pet/idle.webm`

这解决了“桌宠不会动”的问题，但它仍不是八方向转头素材。真正的鼠标方向跟随必须等待合格的只转头视频并完成逐帧校准。

在用户提供八方向视频前，禁止：

- 用 `angle / 360 * frames` 做线性映射；
- 旋转或镜像整个熊猫伪造头部转向；
- 用 AI 重绘替换参考角色。

合格视频到位后的处理门槛：先抽取带帧号 contact sheet，人工确认每个实际朝向，再显式写出类似 `{ center: 0, up: 14, upRight: 27, ... }` 的 `ANGLE_KEYS`；只有八方向在本地逐项验证通过后才启用鼠标跟随。

## Windows 单文件打包

```bash
npm install
npm run dist:win
```

输出目录为 `release/`，目标是 `portable` 单文件 EXE，不显示控制台窗口。Electron 方案复用现有 React、插件素材和全屏休息逻辑；另做 Python/PyInstaller 版本会形成第二套 UI、计时和数据存储代码，不适合作为当前商业项目的升级路径。

正式分发前还需要 Windows 代码签名证书，否则 SmartScreen 可能显示“未知发布者”。
